    •

LAYER 0
A picture is a grid

  
A frame of video is a rectangle of pixels, and each pixel is three numbers: red, green, blue. A 1080×1920 reel frame is about two million of them. Everything above this layer is a way of deciding which numbers go where.


  an 8×4 frame                     one pixel
 ┌──┬──┬──┬──┬──┬──┬──┬──┐        ┌─────────────┐
 │  │  │░░│▓▓│▓▓│░░│  │  │        │ r = 255     │
 ├──┼──┼──┼──┼──┼──┼──┼──┤        │ g = 138     │  → orange
 │  │░░│▓▓│██│██│▓▓│░░│  │  ───►  │ b =  61     │
 ├──┼──┼──┼──┼──┼──┼──┼──┤        └─────────────┘
 │  │░░│▓▓│██│██│▓▓│░░│  │
 ├──┼──┼──┼──┼──┼──┼──┼──┤        ASCII cheat: map brightness
 │  │  │░░│▓▓│▓▓│░░│  │  │        to a character  " .:-=+*#%@"
 └──┴──┴──┴──┴──┴──┴──┴──┘


  
That ASCII trick is real: press ASCII on the player above and the same video is drawn with characters instead of pixels. Same numbers, different display.

LAYER 1
A frame is a function of time

  
Video is frames shown fast, usually 30 per second. The naive approach stores every frame. The Remotion approach stores a function: give it a frame number n, it returns the picture. This is the single most important idea in the whole stack. In real Remotion you get n from useCurrentFrame().


   n = 0       n = 1       n = 2       n = 3
  ┌──────┐    ┌──────┐    ┌──────┐    ┌──────┐
  │●     │    │  ●   │    │    ● │    │     ●│     draw(n) puts the
  └──────┘    └──────┘    └──────┘    └──────┘     dot at x = 10 + 4n
  ◄──────────── 1/30 s each ────────────►



// the smallest possible "video engine"
function draw(ctx, n) {
  ctx.clearRect(0, 0, 640, 360);
  ctx.fillRect(10 + n * 4, 170, 20, 20);   // position depends only on n
}

  
Because the picture depends only on n, you can jump to any frame instantly, render frames in parallel, and get the same result every time. That property is called determinism, and it's why the repo ships a seeded random number generator (mulberry32): even "random" particles must land in the same place on every render.

LAYER 2
Interpolate: frames in, values out

  
Writing 10 + n * 4 by hand gets old. interpolate says "between frame 30 and 55, go from 0 to 260". clamp keeps the value pinned once it arrives. An easing function bends the straight line so motion starts fast and lands softly, the way real objects move.


 value
  260 ┤                 ╭━━━━━━━━━━━  clamp: holds at 260
      │             ╭───╯
      │         ╭───╯        easeOut: quick start,
      │      ╭──╯                     gentle landing
      │    ╭─╯
    0 ┼━━━━╯  clamp: holds at 0
      └────┬────────────┬──────────► frame
           30           55





  
What is clamp, and why does it matter here?

  
clamp(x, lo, hi) means "keep x between lo and hi". Inside interpolate, it decides what happens outside the frame range. Without it, the math keeps going: before frame 30 the value goes negative, and after frame 55 it keeps growing forever, so a title that should stop in place flies off screen.

  
Our from-scratch version always clamps. Remotion's does not: its default is to extend. That is exactly why the repo defines a reusable clamp option on line 13 of primitives.tsx and why CLAUDE.md line 20 tells Claude "always clamp". Drag the slider to see the difference.

-

    
clamp
-

    
interpolate(frame, [30, 55], [0, 260]). The shaded band is the intended range 0–260. Outside frames 30–55, "extend" leaves the band; "clamp" stays at the edge.

  


// JavaScript
const clamp = (x, lo, hi) => Math.min(hi, Math.max(lo, x));
clamp(300, 0, 260);   // 260
clamp(-40, 0, 260);   // 0

# Python
def clamp(x, lo, hi): return max(lo, min(hi, x))

// Remotion: clamping is an option you pass
interpolate(frame, [30, 55], [0, 260], {
  extrapolateLeft: "clamp",
  extrapolateRight: "clamp",
});

/* CSS has one too: font size grows with the screen, but stays 16–40px */
h1 { font-size: clamp(16px, 5vw, 40px); }

  
Clamp shows up anywhere a value has hard limits: color channels (0–255), opacity and volume (0–1), progress bars (0–100%), a camera that must not scroll past the edge of a map.

LAYER 3
Spring: physics instead of curves

  
Easing curves are drawn by a designer. A spring is simulated: a weight on a spring pulled toward 1, slowed by friction. Each frame we compute the force, update the velocity, then the position. Low damping overshoots and wobbles; high damping settles calmly. Remotion's spring() works on the same principle with the same default numbers.

LAYER 4
Compositions and sequences

LAYER 5
The renderer: frames to MP4

  
A player calls renderFrame 30 times a second. An exporter calls it once per frame as fast as it can, saves each picture, and hands the pile to ffmpeg, which compresses them into an MP4.


  for n in 0..149:                         ┌────────────┐
      renderFrame(ctx, comp, n) ──► PNG ──►│ frame_000  │
                                           │ frame_001  │
                                           │    ...     │──► ffmpeg ──► out.mp4
                                           │ frame_149  │
                                           └────────────┘
  real Remotion: opens your React page in headless Chromium, sets the frame,
  screenshots it, repeats. It bundles its own Chromium + ffmpeg.



// browser player loop (what drives the demo above)
let frame = 0, last = performance.now();
function tick(now) {
  if (now - last >= 1000 / comp.fps) {
    frame = (frame + 1) % comp.durationInFrames;
    renderFrame(ctx, comp, frame);
    last = now;
  }
  requestAnimationFrame(tick);
}

Same engine in Python

  
To prove the ideas aren't tied to JavaScript, here is Layers 0 to 5 in about 40 lines of dependency-free Python. A ball springs down and slides across your terminal, drawn in ASCII. Save it as mini_motion.py and run python3 mini_motion.py.


import math, sys, time

W, H, FPS, DURATION = 48, 12, 15, 45
RAMP = " .:-=+*#%@"          # Layer 0: brightness → character

def clamp(x, lo, hi):
    return max(lo, min(hi, x))

def interpolate(frame, f_range, v_range, ease=lambda t: t):   # Layer 2
    (f0, f1), (v0, v1) = f_range, v_range
    t = clamp((frame - f0) / (f1 - f0), 0, 1)
    return v0 + (v1 - v0) * ease(t)

def ease_out(t):
    return 1 - (1 - t) ** 3

def spring(frame, fps, stiffness=100, damping=10, mass=1):     # Layer 3
    x, v, dt = 0.0, 0.0, 1 / fps
    for _ in range(frame):
        force = -stiffness * (x - 1) - damping * v
        v += force / mass * dt
        x += v * dt
    return x

# Layer 1 + 4: a component answers "how bright is pixel (x, y) at frame n?"
def ball(frame, x, y):
    cx = interpolate(frame, (0, 25), (4, W - 5), ease_out)
    cy = interpolate(spring(frame, FPS), (0, 1), (-3, H / 2))
    d = math.hypot((x - cx) / 2, y - cy)   # /2 because characters are tall
    return clamp(3 - d, 0, 1)

def render(frame):                                             # Layer 5
    return "\n".join(
        "".join(RAMP[int(ball(frame, x, y) * (len(RAMP) - 1))] for x in range(W))
        for y in range(H)
    )

if __name__ == "__main__":
    for f in range(DURATION):
        sys.stdout.write("\033[H\033[J" + render(f) + f"\nframe {f:02d}/{DURATION - 1}\n")
        sys.stdout.flush()
        time.sleep(1 / FPS)

LAYER 6
Skills: teaching Claude the craft

  
Layers 0 to 5 are a video engine. Nothing so far involves AI. Layer 6 is where Claude enters. A skill is a folder holding a SKILL.md file: Markdown with a short header. Claude Code reads every skill's name and one-line description at the start of a session, which is cheap. When your request matches a description, it reads the full file. No plugins, no config, no code.

 │   "visual design..."  │         │ → follows its rules while    │
 │  remotion-motion:     │         │   writing code               │

A from-scratch version of a skill looks like this. The real ones are longer, but the shape is identical:


.claude/skills/motion-design/SKILL.md
───────────────────────────────────────
---
name: motion-design
description: Visual design system for motion graphics. Use for any
  video, reel, ad or animated post: color, type, spacing, depth.
---
# Motion design

## Non-negotiables
- Never animate linearly. Entrances use easeOut or a spring.
- One idea per scene. Hold each message at least 1.5 s.
- Type: one display face, one body face. Headlines ≥ 8% of frame height.
- Move the camera between scenes instead of hard cuts.

## "Make it premium" checklist
- [ ] layered shadows, not one flat shadow
- [ ] spacing on an 8 px grid
- [ ] nothing touches the frame edge (safe margin ≥ 6%)

  
This is why the README frames the two skills as taste + mechanics. motion-design encodes judgment a designer would bring. remotion-motion encodes the build workflow, render commands, formats and Remotion gotchas an engineer would bring.

LAYER 7
The orchestrator: Claude Code runs the loop

  
CLAUDE.md sits at the repo root. Claude Code reads it automatically whenever a session opens in that folder. It defines the process: idea → style → build → render. Claude confirms the concept and format, confirms the look, writes a composition, then checks still frames before rendering the full video.


  you: "10s kinetic intro for Nova, 9:16"
        │
        ▼
  ┌───────────────┐  reads   CLAUDE.md          (the process)
  │  Claude Code  │ ───────► SKILL.md × 2       (taste + mechanics)
  │  (agent loop) │ ───────► src/lib/primitives (reusable moves)
  └──────┬────────┘
         │ 1 IDEA   asks: audience? length? one core message?
         │ 2 STYLE  proposes palette + type + mood, waits for OK

  │        ▼                                 │  │ text clipped? too

  │        │ no                              │

  └──────────────────────────────────────────┘

An agent loop is simple at heart: the model picks a tool (read a file, write a file, run a command), sees the result, and picks the next one until the goal is met. Here it is in pseudocode:


context = [CLAUDE_md, skill_descriptions, user_request]
while True:
    action = model.next_step(context)       # e.g. "write NovaIntro.tsx"
    if action.kind == "done":
        break
    result = run_tool(action)               # edit file / run remotion still / ...
    context.append(action, result)          # the model sees what happened

  
The desktop app is just a window onto this loop. You pick the project folder in the Code tab, Claude Code finds CLAUDE.md and the skills inside it, and every file it writes and command it runs shows up for you to approve or review.

Glossary

  
Each entry says what the thing is, when you'd reach for it, where to learn more, and where it shows up in the original repo. Dotted-underlined words elsewhere on the page jump here.

  

    
pixel / frameLayer 0

      A pixel is one dot of color (red, green, blue numbers). A frame is one full picture made of pixels.
      When: always. Formats are named by their pixel size, like 1080×1920 for a vertical reel.
      Pixel (Wikipedia)Root.tsx L12: common formats

    
fpsLayer 1

      Frames per second. At 30 fps, 1 second = 30 frames, so "frame 45" means 1.5 s in.
      When: converting seconds to frames. 30 is the default; 60 for fast action, at double the render time.
      Frame rate (Wikipedia)useVideoConfig (Remotion)remotion-motion L123

    
useCurrentFrame()Layer 1

      Remotion's way of handing your component the current frame number n. Everything that moves is computed from it.
      When: at the top of every animated component.
      Remotion docsKineticIntro L12primitives L20

    
determinismLayer 1

      Same frame number in, same picture out, every time. Renders can then run in any order or in parallel.
      When: always. Math.random() or Date.now() inside a component breaks it and makes things flicker.
      random() (Remotion)remotion-motion L130: the flicker gotcha

    
mulberry32Layer 1

      A tiny seeded random-number generator. Same seed, same "random" sequence, so particles land in the same spots on every render.
      When: confetti, stars, noise, anything that should look random but stay stable.
      PRNGs (Wikipedia)Math.imul (MDN)primitives L78–86

    
lerpLayer 2

      Linear interpolation: a + (b - a) * t. At t = 0 you get a, at t = 1 you get b, halfway gives the midpoint.
      When: blending any two numbers, positions, sizes or colors by a 0-to-1 amount.
      Linear interpolation (Wikipedia)primitives L16used in Scene, L52

    
interpolate()Layer 2

      lerp with a frame range attached: "from frame 30 to 55, go from 0 to 260". It works out t for you.
      When: precise, timed motion like a fade over 20 frames or a slide that must finish on a beat.
      Remotion docsKineticIntro L13: light sweepMaskUp L28

    
clampLayer 2

      Pin a number inside a range: anything below the minimum becomes the minimum, anything above the maximum becomes the maximum. clamp(300, 0, 260) is 260. clamp(-40, 0, 260) is 0.
      When: an animation must stop where it lands instead of drifting past it. Also color channels (0–255), volume (0–1), progress bars, and responsive font sizes. See the live demo.
      Clamping (Wikipedia)extrapolate options (Remotion)CSS clamp() (MDN)primitives L13: definitionCLAUDE.md L20: "always clamp"

    
easing / cubic BézierLayer 2

      A function that bends progress t so motion speeds up or slows down. A cubic Bézier defines the bend with four numbers. The repo's APPLE curve is (0.16, 1, 0.3, 1): very fast start, long gentle settle.
      When: every entrance and exit. Linear motion reads as robotic, which is why the repo bans it.
      Play with the APPLE curveeasings.netEasing (Remotion)primitives L10–15

    
spring()Layer 3

      Motion from a simulated spring instead of a drawn curve. Stiffness is how hard it pulls, damping is friction, mass is weight.
      When: things that should pop or bounce, like buttons, icons and notifications. Use interpolate when timing must be exact.
      Remotion docsHooke's lawSemi-implicit Eulerremotion-motion L65–66

    
compositionLayer 4

      A video's spec: an id, a component to draw, width, height, fps and length in frames. You render by id.
      When: adding any new video. One file in src/compositions/, one line in Root.tsx.
      Remotion docsRoot.tsx L14–20

    
sequence / SceneLayer 4

      Show something only between two frames. Remotion's built-in is <Sequence>. The repo writes its own Scene instead, which also adds a camera push in, slow drift and zoom out.
      When: splitting a video into beats that start and end at set times.
      Sequence (Remotion)Scene, primitives L38–56KineticIntro L19–30

    
mask / clipLayer 4

      A window that hides anything outside it. Text that starts below the window and slides up appears to rise out of nowhere.
      When: kinetic typography, the "line rises into place" look.
      canvas clip() (MDN)CSS overflow (MDN)MaskUp, primitives L25–30

    
layer orderLayer 4

      Draw back to front; later layers cover earlier ones. Called the painter's algorithm.
      When: stacking background, content and overlays such as vignettes.
