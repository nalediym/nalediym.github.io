dispatches from the substrate · no. 04 · helsinki

It was supposed
to be a terminal
emulator.

A short fiction about the eleven weeks in 1991 when a 386 bought to run Prince of Persia quietly turned into an operating system — and nobody, least of all the author, noticed in time to stop it.

filed under HISTORICAL_FICTION accuracy mode: mr_robot est. read 9 min

The modem was the whole problem, really. The university kept a MicroVAX humming somewhere in the basement of the computer-science building, and the only way to reach its Unix from the apartment on Petersgatan was to dial in over a 2400-baud line and let some piece of software pretend to be a terminal. MINIX shipped with one. It was fine. Fine was the word that had started to itch.

He had bought the machine in January — an Intel 80386, 33 megahertz, four megabytes of RAM, a forty-megabyte disk, partly on the honest pretext of coursework and partly so he could play Prince of Persia without the borrowed Sinclair choking on it. By autumn the games were installed and ignored. What he kept coming back to was the chip's manual, and one specific thing the 386 could do that the 286 in everyone else's machine could not: it could be told, in hardware, to run two things at once and switch between them so fast it looked like both.

So the terminal emulator was never the point. The terminal emulator was the excuse.

scene one · two letters

He wrote it bare-metal. Not as a MINIX program — that would have been the sane thing, and it would have taught him nothing about the chip. He wrote two independent tasks. One did nothing but write the letter A to the screen, forever. The other wrote B. The 386's task gate would flip between them on the timer interrupt, and if he'd wired the descriptor tables correctly, the screen would fill with proof.

The screen in text mode was just memory. Address 0xB8000. Two bytes per cell — character, then attribute. You didn't print to it. You wrote bytes into it, like writing to any other address, and the CRT controller did the rest. He liked that. No abstraction lying to him about what was underneath.

386 · real → protected mode · tasks A/B
; task A — write 'A' at the top-left cell of text video memory ; segment 0xB800 in real-mode terms; physical 0xB8000 mov ax, 0xB800 mov es, ax mov byte [es:0], 'A' ; the character mov byte [es:1], 0x07 ; grey on black .loop: jmp .loop ; spin. the timer will yank us out. ; the trick is in the IDT: the timer IRQ (vector 0x08) is a TASK gate, ; not an interrupt gate. so the CPU does a full hardware task switch — ; it dumps every register into task A's TSS and loads task B's. for free. ltr ax ; load task register, point it at the TSS

Real mechanism. The 386 could switch tasks in hardware via the Task State Segment — exactly the chip-specific feature that made the kernel fast, non-portable, and, later, controversial.

He ran it. The screen did this:

/dev/console
AAAAAAAAAAAAAAAAAAAAAAAAAAAABBBBBBBBBBBBBBBBBBBBBBBBBB BBBBBBBBBBBBBBBBBBBAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAABBBBBBBBBBBBBBBBBBBBBBB

That ragged seam where the As gave way to Bs — that was the timer interrupt firing, the chip stuffing one task's whole soul into a TSS and loading another's. That was multitasking, in the apartment, on a machine that had no business doing it yet. He sat with it for a long time. There is a particular silence that follows the moment a thing you only half-believed would work, works.

It is not that he decided to write an operating system. It is that he kept needing one more thing, and each thing he needed was the next layer down.
scene two · the slide

Two tasks writing letters is a toy. But to actually use it as a terminal — to dial the VAX and download files while connected — he needed to read and write the serial port himself. The 8250 UART, ports 0x3F8 and up. in and out instructions. Fine. He wrote a driver.

Then he wanted to keep the files he downloaded. Which meant writing them to disk. Which meant a disk driver — the AT hard-disk controller, registers at 0x1F0. Fine. He wrote that too. And once bytes were landing on the platter, they had to land somewhere structured, which meant a filesystem. He could have invented one. Instead he made his read and write the MINIX filesystem — same inode layout, same block bitmap — so the files would still be there, still readable, when he booted back into MINIX to compile the next version.

He stopped one evening and counted what he had: a thing that booted itself, switched between processes, talked to the serial line, drove the disk, and understood a filesystem. Somewhere in the slide from A and B to here, the terminal emulator had quietly died and been replaced by something with no name and every organ of an operating system.

minix shell — building the thing that will replace minix
# bootsector is 8086-clean, so it goes through as86/ld86, # not gas. bruce evans' toolchain. 512 bytes, ends in 0xAA55. $ as86 -0 -a -o boot/bootsect.o boot/bootsect.s $ ld86 -0 -s -o boot/bootsect boot/bootsect.o # the rest is C, compiled with gcc ported onto minix. # -O because it has to be small. -fstrength-reduce because # every cycle on a 33MHz box is a cycle you actually feel. $ gcc -O -Wall -fstrength-reduce -fomit-frame-pointer \ -fcombine-regs -mstring-insns -c -o kernel/sched.o kernel/sched.c $ ls -F boot/ fs/ include/ kernel/ lib/ mm/ Makefile README $ wc -l kernel/*.c fs/*.c mm/*.c | tail -1 10239 total

All real: the boot sector went through as86/ld86 while the kernel proper was C through gcc, and the whole thing was bootstrapped inside MINIX — the OS it was about to make obsolete on his own machine.

scene three · the post

It compiled. It booted off a floppy. It could not do very much — no networking, you needed MINIX just to build it, and it ran on the 386 and nothing else on Earth. He thought it was a hobby. He thought it would stay small. He sat down at the MicroVAX session one night in late August and opened a newsreader, and posted to comp.os.minix the most consequentially wrong prediction in the history of the field: that it was "just a hobby, won't be big and professional like gnu."

rn — comp.os.minix — 25 Aug 1991
Newsgroups: comp.os.minix Subject: What would you like to see most in minix? Summary: small poll for my new operating system Hello everybody — he tells them it's a free OS, a hobby, nothing on the scale of GNU. He tells them it will only ever run on the 386, because he uses the chip's own task switching and there is nothing portable about it. He asks what features people would want. He is, he writes, doing this for fun, and it will probably never support anything but AT-class disks, because that is all he has. -- Linus Torvalds torvalds@kruuna.helsinki.fi

Paraphrased from the real Usenet post of 25 August 1991 — including the genuinely-made claims that it would be 386-only and AT-disk-only. Both turned out to be hilariously temporary.

He wanted to call it Freax — free, plus freak, plus the obligatory x. He thought that was the name. But when he uploaded the source for version 0.01 to the university FTP server, the administrator who gave him the directory — Ari Lemmke — quietly disliked Freax, and named the folder after the author instead.

ftp.funet.fi — /pub/OS/
ftp> cd /pub/OS ftp> ls drwxr-xr-x minix/ drwxr-xr-x linux/ # <- he had wanted to call it 'freax'. ftp> cd linux ftp> put linux-0.01.tar.gz 226 Transfer complete. 73091 bytes sent

And so the most-deployed piece of software in human history — the thing that would one day run the phones, the servers, the rovers, the markets, the routers between you and this page — was named by accident, by a sysadmin with a directory to fill and an opinion about a bad pun. The author kept calling it Freax for a while. Nobody listened. The folder won.

The 386-only decision was a confession of laziness that became the architecture. The name was a vetoed pun. The whole thing was a terminal emulator. None of it was supposed to matter.

where the fiction stops

FACT — Torvalds bought a 33MHz 386 with 4MB RAM in early 1991, partly to play games. He wrote a bare-metal terminal emulator to dial into the university's Unix, and the A/B task-switching experiment using the 386's hardware TSS is the real origin moment. Needing to download and store files drove him to write a disk driver and a MINIX-compatible filesystem, at which point it had become an OS.

FACT — The boot sector really was built with Bruce Evans' as86/ld86; the kernel was C through gcc, bootstrapped under MINIX. The 25 Aug 1991 post to comp.os.minix really did call it "just a hobby" and really did claim it would stay 386-only and AT-disk-only. He wanted to name it Freax; Ari Lemmke named the FTP directory linux and it stuck. Version 0.01 shipped to ftp.funet.fi in September 1991.

FICTION — The interior monologue, the apartment on Petersgatan, the "long silence," the exact terminal transcripts and byte counts. The mechanisms are accurate; the scenes around them are invented. (Petersgatan is plausible Helsinki, not a documented address — treat it as set dressing.)
